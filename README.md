# 城市滑板公园 · 未成年人入场与伤情处置系统

React + TypeScript + Tailwind CSS 单页应用，nginx 容器化一键部署。系统围绕
**预约 → 闸口核验 → 护具柜绑定区域 → 在场看板 → 巡场提醒/伤情串联 → 家长通知与区域策略调整**
的完整闭环，联动五个角色。

## 原始需求

> 设计城市滑板公园未成年人入场与伤情处置页面，可使用 React、TypeScript 和 Tailwind CSS。家长为未成年人预约入场后，页面记录年龄、滑行水平、紧急联系人、是否同意进入高级区、是否租赁护具和历史受伤情况；闸口核验后，儿童的入场状态会影响护具柜和场地区域权限。护具柜发放头盔、护膝和护腕后，页面会把护具编号和可进入区域绑定，未领取护具的孩子只能进入基础练习区。场地管理员看到的是当前在场未成年人、护具穿戴状态、可进入区域和陪同家长位置；教练或巡场员发现孩子进入高难度区、未佩戴护具或摔倒后，可以在移动端发起提醒或伤情记录。若孩子摔倒、头盔破损、家长不在现场、孩子坚持继续滑或需要送医，页面要把巡场员记录、护具状态、现场照片、家长确认和处置结果串起来。家长端收到具体伤情、现场处理、是否建议离场和后续复查提示。伤情事件会影响孩子当天是否还能继续滑、下次入场是否需要重新授权、是否必须租赁护具或先完成教学确认，场馆也能根据伤情集中区域调整巡场路线和障碍开放策略。

## 一键启动（宿主 Docker Compose）

```bash
cp .env.example .env        # 可按需修改 CC_PUBLISH_PORT
docker compose up -d --build
```

查看实际映射端口（并行任务环境下不要假设固定端口）：

```bash
docker compose port app 8080
# 例如：0.0.0.0:3009
```

浏览器访问：`http://host.docker.internal:<上一步输出的宿主端口>`（本机评测即 `http://localhost:3009`）。

健康检查：容器以非 root 用户 `nginx` 运行，内置 `HEALTHCHECK`，`docker ps` 中状态为
`healthy` 即通过。停止并释放资源：

```bash
docker compose down
```

> 本应用为纯前端演示（无外部数据库依赖），数据保存在浏览器 localStorage；
> 页面右上角「↺ 重置演示数据」可随时恢复初始演示数据。

## 五个角色 / 页面入口（顶部切换，无需登录）

| 角色 | 能力 |
| --- | --- |
| 👨‍👩‍👧 家长端 | 预约入场（年龄/滑行水平/紧急联系人/高级区授权/租赁护具/历史受伤）、更新陪同位置、接收伤情与处置通知、查看后续限制 |
| 🚦 闸口核验 | 搜索孩子/家长/护具编号，人证核验后放行（booked→checked_in），离场签退收回权限；展示核验后将获得的区域权限 |
| 🪖 护具柜 | 向在场孩子发放头盔/护膝/护腕（扫码或系统分配编号），编号与可进入区域绑定；登记头盔破损；未领齐只显示基础练习区 |
| 🗺️ 场地管理员 | 在场未成年人看板（护具穿戴、编号、可进入区域、当前位置、陪同家长定位）、KPI、区域开放/障碍与加强巡场策略、伤情流转总览 |
| 📱 巡场/教练（移动端样式） | 按伤情热度排序的巡场路线、发起提醒、四步伤情处置向导、提醒可升级为伤情 |

## 建议验收路径（一条主线走通全部联动）

1. **家长端**：查看/新建预约（勾选租赁护具、高级区授权），提交后状态「待核验」。
2. **闸口核验**：搜索姓名 →「放行入场」；状态变「在场」，可离场签退。
3. **护具柜**：选择孩子，逐件发放头盔/护膝/护腕，观察「护具编号 × 区域绑定」表与右侧可进入区域：
   - 只发头盔 → 仅 **基础练习区**；
   - 三件齐全（进阶水平）→ 基础 + **街式区**；
   - 高级水平且家长授权（如陈一帆）→ 再加 **高级 U 池区**；
   - 点「登记头盔破损」→ 街式/高级权限立即收回。
4. **管理员看板**：看到每名孩子的穿戴状态、护具编号、区域权限、当前位置、家长陪同位置与未处理提醒。
5. **巡场/教练移动端**：
   - 对赵豆豆可先「发起提醒」（进入高难度区/未佩戴护具），提醒出现在管理员端，可关闭或**升级为伤情**；
   - 对任一在场孩子点「伤情记录」，依次完成四步：
     1. **巡场记录**：多选触发情形（摔倒/头盔破损/家长不在/坚持继续滑等）+ 严重度 + 记录 + 护具快照；
     2. **现场照片**：拍照/上传（自动压缩）或使用示意照片 + 说明；
     3. **家长确认**：自动展示陪同家长/紧急联系人/定位，家长不在现场或孩子坚持继续滑时有专门提示，记录电话确认；
     4. **处置结果**：现场处理、是否建议离场、是否送医、复查提示；规则引擎按严重度+原因**预填限制**（当天能否继续滑、下次是否重新授权、必须租护具、先完成教学确认），可人工调整。
6. 闭环后：**家长端**收到「具体伤情/现场处理/是否建议离场/复查提示/后续限制」通知；
   管理员看板该孩子显示「当天停止滑行」并被收回街式/高级权限；孩子卡片与护具柜显示「必须租赁全套护具」；
   非轻微伤情自动对事发区域开启「加强巡场」，管理员端巡场路线按伤情集中度重新排序，并可一键关闭区域/暂停障碍。
7. **规则验证**：将高级 U 池区「临时关闭」→ 陈一帆的区域徽章立即失去高级区；严重伤情处置后该孩子当天仅剩/失去场地权限。

## 技术结构

```
src/
  types.ts          领域模型（孩子/护具/提醒/伤情四阶段/区域策略）
  engine.ts         权限与后果引擎：allowedZones / hasFullGear / deriveRestrictions / incidentsByZone
  seed.ts           演示数据
  store.tsx         Context + Reducer + localStorage 持久化
  ui.tsx            基础组件（Card/Badge/Button/Input/ZoneDots…）
  App.tsx           角色切换外壳
  views/
    ParentView.tsx  家长：预约表单 + 我的孩子 + 伤情通知
    GateView.tsx    闸口核验
    LockerView.tsx  护具发放与区域绑定
    AdminView.tsx   管理员看板 + 区域策略
    PatrolView.tsx  移动端：提醒 + 四步伤情处置向导
Dockerfile          多阶段构建（node:22 构建 → nginx:1.27-alpine 运行，非 root + HEALTHCHECK）
nginx.conf          SPA history 回退，非 root 监听 8080
docker-compose.yml  仅发布应用端口 ${CC_PUBLISH_PORT}:8080
```
